# Phase 6C — Windows installer verification

## Local deliverable

- Version: **0.1.0**, JobTrack's first independent Windows test version.
- File: `dist-desktop/JobTrack-Setup-0.1.0.exe` (259,977,239 bytes; 247.93 MiB).
- SHA-256: `3885ec775baaf02ad65c2dcf5e2c5c2d22eebb943493516c73838467b8c914c0`.
- A matching `.exe.sha256` sidecar is generated by the build.
- No GitHub Push/Release, automatic updater or dependency upgrade.

The previous 1.1.22 was inherited from upstream. No JobTrack installation or
release existed at the start of this phase, and JobTrack has its own App ID,
so 0.1.0 is an independent baseline rather than a downgrade of JobSync. The
existing release-check endpoint already targets the JobTrack repository and
uses the root package version. Root package, lockfile, staged app, web UI and
NSIS use 0.1.0. Windows represents ProductVersion as 0.1.0.0 (zero build
component), while FileVersion and Installed Apps show 0.1.0.

## Actual Windows installation

The actual current-user NSIS installer was executed with `/S`. This is a real
installation on Windows, not unpacked-directory testing. All application
interactions use independent `JOBTRACK_HOME` directories inside the ignored
`.local-runtime-test/` directory. The formal data root is never reset or used
for fixture registrations.

- Installation directory: `%LOCALAPPDATA%\Programs\jobtrack-desktop`.
- Installed Apps: **JobTrack 0.1.0**; correct version and owned uninstaller.
- Desktop and Start menu: **JobTrack.lnk**, both targeting the installed EXE.
- Both shortcuts use AppUserModelID `io.github.yueyehuanxiangqu.jobtrack`.
- Installed EXE matches the packaged payload; product/file description is JobTrack.
- The real desktop shortcut launches without system Node on PATH. Its window
  uses JobTrack, serves version 0.1.0, and exits with its owned backend on close.
- Current-user installation does not request administrator elevation.

The one-click NSIS target intentionally derives the installation directory from
the internal package name (`jobtrack-desktop`). Initial verification assumptions
about `Programs\JobTrack`, an optional InstallLocation registry value and a
three-component Windows ProductVersion were corrected to the actual NSIS/Win32
formats. No installation-package or business-code change was required.

  real Activity Calendar, CSV/PDF, ZIP preflight/restore/snapshot/rollback,

- Real shortcut launch/close: **2 checks**.

  **7 targeted Vitest tests**. Navigation: **25 targeted Vitest tests**.
  TypeScript, ESLint and production build passed.
- The full 2,032-test suite from Phase 6A/6B was not repeated.

The 33 business-regression groups above ran against the first 0.1.0 installer.
Visual review then found the old generic briefcase glyph still present in the
sidebar and mobile menu. Those two brand links now use the existing J-Track SVG;
navigation tests cover both. The final revision was rebuilt for this change,
with a focused installed-app brand/version/login and lifecycle verification
rather than another complete business regression. A session interruption left
an incomplete compression cache; only that generated archive was removed before
resuming NSIS packaging from the completed final application payload.

## Installer lifecycle and protected data

Passed on this Windows account using only the installation created by this
phase (not a VM and not another application's installation):

1. Install 0.1.0 and perform the installed business regressions.
2. Reinstall over the same version, uninstall, reinstall, and reopen retained
   fixture data. The final brand revision also passed its own replacement,
   uninstall and reinstall cycle using the exact delivered installer.
3. Uninstall removes the entire owned program directory, desktop/Start menu
   shortcuts and uninstall record, while requesting no user-data deletion.
4. Before/after file-path and SHA-256 inventories confirm all three isolated
   test homes (databases, files, runtime keys, profiles and backups) are
   byte-identical across each final installer operation, before reopening apps.
5. After final reinstall, wrong-password rejection, logout/relogin, retained
   attachment download, both job-document slots and original runtime keys were
   checked again. The actual desktop shortcut launches and closes the final
   installed app and backend without system Node on PATH.

The formal `%LOCALAPPDATA%\JobTrack` home and
`%LOCALAPPDATA%\JobTrack-Migration-Backups` also remain byte-identical to the
fingerprints captured before installation work. No formal account was created
or reset. The default root remains JobTrack; test processes alone receive an
explicit isolated `JOBTRACK_HOME`. `%LOCALAPPDATA%\JobSync` was not recreated.
The final JobTrack installation and its normal shortcuts are left installed,
with all test windows/services closed, ready for the user's own first use.

## Icon and payload audit

The unpacked payload was audited across 23,953 files. No environment/key
configuration files, user SQLite databases, test-data trees, personal document
files, obsolete JobSync artwork or credential-pattern findings were detected.
Vendor SDK code is not represented as user credentials. The full original MIT
license is present and unchanged.

The selected A — J-Track's exact seven PNG frames (16, 24, 32, 48, 64, 128, 256px)
are embedded in both the app EXE and NSIS installer. Electron uses the matching
256px PNG; the Installed Apps icon file matches the selected multi-resolution
ICO byte-for-byte. Small-size optical adjustments are retained.

## JobSync residue cleanup

The user had already uninstalled JobSync. No old uninstaller was run. No matching
old installation directory, desktop/Start menu/pinned `.lnk`, uninstall record
or Roaming home was found. Registry contents were not batch-deleted.

The final residue scan found `%LOCALAPPDATA%\jobsync-desktop-updater` containing
only an `installer.exe` whose Windows product metadata identifies JobSync
1.1.22. It is an old NSIS installer cache, separate from both data/recovery roots.
Its sole file's hash and identity were rechecked before removing this cache
after the new installation lifecycle passed.

Seventy old test temporary directories were proved to belong to this repository
using test creator code, exact fixture paths, synthetic bytes and test-account
signatures, then removed after checking absolute paths and rejecting reparse
points. Two directories could not be proved safe and were preserved:

- `%TEMP%\jobsync-backup-Et8lQX`
- `%TEMP%\jobsync-backup-RjR26X`

After the final lifecycle passed, removed these ignored obsolete project files:

- `dist-desktop/JobSync-Setup-1.1.22.exe`
- `dist-desktop/JobSync-Setup-1.1.22.exe.blockmap`
- `dist-desktop/JobSync-Setup-1.1.22.exe.sha256`
- `.next-local/` (unused former browser production build)

Every recursive removal checks the exact absolute parent/name and rejects
reparse points. The old installer and updater cache were identified by hash;
the build cache had its generated manifests and no Git-tracked files. Current
desktop staging, packaged app, new installer, checksums and recovery backups
are retained. Shared Windows icon caches and taskbar registry data are untouched.

`F:\Programming\Applications\jobsync`, the JobTrack source/Git history,
`%LOCALAPPDATA%\JobTrack`, and `%LOCALAPPDATA%\JobTrack-Migration-Backups`
are protected. No historical schema migration or MIT copyright was changed.

## Not verified / distribution limits

- Full machine reboot: not performed; application restart is tested.
- Native Windows UI inspection was unavailable (Computer Use native pipe could
  not connect after documented retries). Installer wizard appearance, pinned
  taskbar visual inspection and a separate Settings UI screenshot are not
  claimed; registry, shortcut, executable and app-window identities were checked.
- Observed display scale: 125% (`devicePixelRatio=1.25`). Separate 100%, 150%
  and 200% DPI sessions were not performed.
- This installer and EXE are **NotSigned**. Local execution passed, but a
  downloaded copy can encounter SmartScreen reputation warnings. No security
  setting or warning was bypassed. See [Microsoft's SmartScreen developer
  guidance](https://learn.microsoft.com/windows/apps/package-and-deploy/smartscreen-reputation).
- Cross-version upgrade from a prior independent JobTrack release cannot be
  tested because none exists. Same-version replacement is the tested update
  analogue; old JobSync migration was covered in Phase 6B.
